# Domain Docs

## Antes de explorar

- Leia `GLOSSARY.md` na raiz.
- Leia os ADRs relevantes em `docs/adr/`.

Se esses arquivos não existirem, prossiga sem apontar sua ausência. Crie documentos de domínio somente quando uma decisão ou termo for realmente resolvido.

## Vocabulário

Use os termos definidos no glossário em nomes de domínio, testes e documentação; não introduza sinônimos que o glossário evita. Se faltar um conceito necessário, registre a lacuna para a skill `/domain-modeling`.

## ADRs

Se uma proposta contradizer um ADR existente, explicite o conflito em vez de sobrescrever a decisão silenciosamente.
